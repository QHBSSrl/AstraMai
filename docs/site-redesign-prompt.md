## 一、产品是什么

**ORhythm** —— 街机音游的查分工具。开发方是 NowMes Software。

支持四个游戏：舞萌 DX（maimai）、中二节奏（CHUNITHM）、
Phigros、osu!

**它有两种形态：**

1. **Android 手机 App**（Flutter 写的，Material 3 + 动态取色）
   —— 查分、看 Best 50、算推分、查别人、和上次比

2. **小米手表 / 手环上的快应用**（Vela 那套）
   —— 抬腕就能看，不用掏手机

**核心功能：**

- 查分：Best 50 / Best 30，含封面、难度、达成率、定数
- 推分计算器：「我想打到 300 分，需要多少达成率？」
  直接给答案，不用自己算
- 成绩对比：和上一次查的比，涨了跌了新进掉出分四类列清楚
- 离线缓存：音游厅在地下信号差，查过一次之后没网也能翻
- 二维码：机台扫码登录
- 手机网桥：**手环没有网络模块**，靠手机 App 中转联网
  （这是这版刚做通的功能，用户最关心的痛点之一）

**版本**：v0.1.3

## 二、用户是谁

真实的音游玩家。他们在机厅排队时掏手机看上一把的成绩，

## 三、硬性技术要求（必须遵守）

**站点是纯静态 HTML，用 Node 脚本拼装，没有框架、没有构建工具链
不要引入 React/Vue/Tailwind CDN。** 原生 HTML + CSS 就够。
允许极少量的原生 JS（比如移动端导航折叠）。

**构建方式：**

```
layout.html         页面骨架，含导航和页脚
pages/<name>.html   每页的正文片段（只有内容，没有 html/head/body）
build.mjs           读 layout + pages，替换占位符，输出到 dist/
```

**layout.html 里可用的占位符（原样保留，不要改名）：**

```
{{TITLE}}         页面标题
{{DESCRIPTION}}   页面描述（meta description / og）
{{CONTENT}}       正文片段的注入点   ← 必须保留
{{VERSION}}       版本号
{{NAV_GAMES}}     导航当前页高亮用的 class（值为 class="nav__link is-active" 或空）
{{NAV_FEATURES}}
{{NAV_CHANGELOG}}
{{NAV_FAQ}}
```

**要产出的页面：**

| 文件 | 内容 |
|---|---|
| `pages/index.html` | 首页 |
| `pages/games.html` | 支持的游戏 |
| `pages/features.html` | 功能详解 |
| `pages/download.html` | 下载 |
| `pages/faq.html` | 常见问题 |
| `pages/changelog.html` | 更新日志（正文由构建注入，见下） |

> `changelog.html` 的正文里要保留一个 `{{CHANGELOG}}` 占位符，
> 构建会把 CHANGELOG.md 转成 HTML 塞进去。

**样式**：全部写在单个 `style.css` 里，用 CSS 变量组织配色。
**不要**引入外部字体（国内访问 Google Fonts 不稳定），
用系统字体栈。

**必须响应式**，手机上看不能崩。下载页在手机上最重要。

## 四、下载信息（必须准确）

真实存在的文件，在 `./releases/` 目录下：

```
./releases/ORhythm-0.1.3-arm64-v8a.apk      17.9 MB   绝大多数手机
./releases/ORhythm-0.1.3-armeabi-v7a.apk    15.5 MB   老设备
./releases/com.nowmes.orhythm.0.1.3.rpk      294 KB   手表/手环
```

**下载页要说清楚的：**

- 手机用户选 **arm64**（99% 的机器都是），不确定也选它
- 装 APK 会提示「未知来源」，允许即可
- **如果装过旧版要先卸载** —— 0.1.3 换了包名
  （`com.astranexus.astramai` → `com.nowmes.orhythm`），
  不卸载会出现两个图标
- RPK 要用手机上的 **AstroBox** 推到手表

## 五、视觉方向（这部分由你决定）

**上一版被老板骂了，原话是「和我刚拉的屎一样」。** 原因我总结了三条，
你避开就行：

1. **首屏只讲手表，完全没提手机 App** —— 而手机 App 才是这一版的主菜。
   信息架构过时了。
2. **纯文字堆砌，一个界面都没展示** —— 用户没法「看到」产品。
3. **首屏占满一屏，信息密度极低** —— 标题大得离谱，往下滚才是干货。

**你的自由：** 深色还是浅色、什么字体大小、什么栅格，你定。
但请满足：

- 首屏就要让人看懂「这是什么 + 能干什么 + 去哪下」
- **必须展示产品长什么样** —— 用 `<img>` 放真实截图（我会提供），
  或者用 HTML/CSS 画一个手机界面预览。不能只有文字。
- 手机 App 和手表要**同时**体现，不要只讲一个
- 下载按钮要在首屏能看到（不用滚动就能找到）
- 整体克制。这是个工具，不是游戏宣传页。

**参考的设计语言**（不是必须照抄，是让你知道它现在什么样）：

App 内的主色是深蓝黑底 `#070b16`，强调色青 `#4fd6ff`、粉 `#ff5f9e`。
难度色：绿 `#22c55e` / 橙 `#f59e0b` / 红 `#ef4444` / 紫 `#a855f7`。
官网如果走深色，和 App 一致会更好；走浅色也行，你自己判断。
