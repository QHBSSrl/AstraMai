## 二、必须真机确认的五项

按**风险从高到低**排。

### ① 成绩卡高度（风险最高）

`ScoreSummary` 是**固定 132px**，右侧统计行从 4 行变成了最多 5 行。

我算的是：可用高度 100px，一行约 18~20px，5 行刚好卡满。
**但行高是按字号反推的，不是实测的。**

**看什么**：舞萌的 B50 查出来后，右侧第一行「旧曲 B35」和最后一行
是否完整、有没有被上下裁掉。

### ② 推分页的按钮条

```
[-5] [-1]   300   [+1] [+5]
```

五个元素挤在 466px 宽里。每个按钮 58px + 中间的数字 40px 字号。

**看什么**：有没有挤成一团、数字有没有被压扁。

### ③ 对比详情页 / 练哪条页的列表

两个页面都用 `<list>` 混排「分区标题行」和「条目行」
（`$item.kind === 'head'` / `'item'`）。

**看什么**：
- 标题行和条目行的高度是否正确（标题 34px、条目 54px）
- 长曲名有没有正常省略（`text-overflow: ellipsis` 在 `<list>` 里不一定生效）

### ④ 离线缓存

**怎么测**：
1. 正常查一次 B50（会写入缓存）
2. 断网（或把服务器地址改错）
3. 再点「查询」

**期望**：显示上次的成绩 + 一行「查询失败。下面显示的是 X 月 X 日 XX:XX 的数据（离线缓存）。」

### ⑤ 对比行

**怎么测**：查完第一次后再查第二次（成绩没变也行）。

**期望**：
- 成绩没变 → **不显示**对比行
- 有变化 → 显示「总 Rating +N · X 首涨 · …」，且**可点**（末尾有 `›`）

## 三、已知的设计取舍（不是 bug）

### 「距下一档」占第 4 行，「公式对拍」降级到第 5 行且条件显示

「公式对拍 一致」是开发用的质量信号，对玩家没意义。
现在只在**对不上时**才出现（那种情况本来就该让用户看到）。

### 掉出 B50 用灰色，不是红色

「掉出」不代表成绩掉了 —— 是别的谱打得更好把它挤出去了。
用红色会让人以为退步。

### 反算「需要打到多少」是「至少」语义

要 1 分而这首打底 2 分时，答案是 10%（实际给 2 分），不是"打不到"。
只有**超过天花板**才算打不到。

### 中二节奏的 rating 对不上是正常的

`player.rating` 和 `b30 之和` 本来就不是一回事，官方算法如此。
代码里 `chunithm/bests.ts` 顶部有注释，别再当 bug 查。

## 四、环境坑（这台机器上开发时踩的）

### 构建"没报 success"之后，不要相信 `dist/`

系统**提交内存**经常跑满（31.5 / 31.7 GB），导致：

- 构建跑不起来，而且**连错误都打不出来**（日志停在 `Compile javascript project`）
- `npm test` 出现**假失败**（重跑就过）
- 失败的构建会把 RPK 写坏 —— 表现为**尺寸异常**（685 KB vs 正常 341 KB），
  但能解压、页面数也对，看不出坏

**每次构建都核对 RPK 大小。正常约 341 KB。**

### Vela 的几个硬限制

| 坑 | 真相 |
|---|---|
| 后代选择器 | **会泄漏到所有同名 class**，不是作用域隔离 |
| `div` 默认 | **`flex-direction: row`**，不是 block |
| 样式作用域 | **页面级** —— B50 页的 `.action` 在 Welcome 页不存在 |
| `margin-top: auto` / `align-self` | **都不生效**（实机验证过） |
| 模板绑错名字 | **不报错，只渲染空白** —— 有 `test/ux-binding.test.mjs` 兜着 |
| `<qrcode>` | **内置组件**，不能 import |

### 改 Vela 代码后

```bash
npm run build:core      # 改了 packages/core 才需要
npm run bundle:core     # core 改动要重新 bundle 进 vela
cd apps/vela && npm run build
```

**`apps/vela/src/common/astramai-core.js` 是自动生成的，不要手改。**
