# 工作单 001：运维数据采集脚本

## 背景（够你判断，不用更多）

我们在做一个「腕上服务器运维」的小工具。手表抬腕看一眼：
CPU / 内存 / 磁盘 / 负载 / 容器异常数。

链路是：

```
被监控服务器  --(你的脚本，定时)-->  我们的中转服务器  -->  手表
```

**你只做最左边那一段**：一个能定时跑、采集本机指标、POST 出去的脚本。

## 输出契约

POST 到中转服务器，body 是 JSON，**字段名和类型一个都不能改**：

```json
{
  "host": "srv-01",
  "ts": 1761289200,
  "cpu": 12.5,
  "mem_used": 1288490188,
  "mem_total": 2013265920,
  "load": [0.52, 0.48, 0.41],
  "disk": [
    { "mount": "/", "used": 42949672960, "total": 107374182400 },
    { "mount": "/data", "used": null, "total": null }
  ],
  "uptime": 864000
}
```

字段说明：

| 字段 | 类型 | 说明 |
|---|---|---|
| `host` | string | 主机名。**取不到就用 `unknown`**，不要抛异常 |
| `ts` | int | **Unix 秒**（不是毫秒）。用 UTC |
| `cpu` | float | 近 1 分钟平均 CPU 使用率，百分比 0–100，**一位小数就够** |
| `mem_used` / `mem_total` | int | **字节** |
| `load` | [float,float,float] | 1/5/15 分钟负载。取不到就给 `[null,null,null]` |
| `disk` | array | 见下 |
| `uptime` | int | **秒** |

`disk` 里每一项：`used` / `total` 是**字节**；读不到就给 `null`（**不要跳过这一项**，空盘符和读不到是两回事）。

## 验收标准

我会一条条查，**请自己在 `from-glm.md` 里贴输出**：

1. `python collect.py --dry-run` → 打印 JSON 到 stdout，**不发网络请求**
2. 输出能通过 `json.loads`，字段齐全、类型对
3. **只用标准库**（目标机可能没有 pip，也可能没有网络装包）
4. 单个文件 ≤ 200 行
5. **任何一项取不到都不能抛异常**，对应字段给 `null` 或兜底值
6. 在 Linux 上跑得起来（我在 Debian 12 上验证）
7. `--help` 有中文说明

## 我这边会做的（你不用管）

- HTTP 上报（含重试、超时、认证）
- 配置文件解析
- systemd unit / 定时任务
- 中转服务器的接收端
- 手表端

**所以你的脚本里不要写 http、不要读配置、不要装依赖。** 只做「采集 + 打印/回调」。
上报部分留一个函数签名给我，比如：

```python
def build_payload() -> dict:
    """采集本机指标，返回符合契约的 dict。"""
```

`--dry-run` 就是这个函数 + `json.dumps`。

## 一些实现建议（不是硬要求）

- CPU 使用率**不要用 `psutil`**（那是第三方）。读 `/proc/stat`，采样两次间隔 1 秒算差值
- 内存读 `/proc/meminfo`，注意 `MemAvailable` 比 `MemFree` 准
- 磁盘用 `os.statvfs`
- 负载读 `/proc/loadavg`
- 这些在 Linux 上都有；**在 Windows 上要优雅退化**（给 null，别崩）
