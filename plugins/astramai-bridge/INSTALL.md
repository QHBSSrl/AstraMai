# 安装与测试（第一轮）

这一轮的**唯一目标**：确认三件事能不能成。

1. 插件能装上
2. 插件能加载（`on_load` 跑起来）
3. **插件能上网** ← 最关键，不通就没意义

手表端一行代码都还没写，所以这轮**不测 `ping`**，只看日志。

---

## ✅ 手机能装插件（这条之前记错了）

**手机上的 AstroBox App 可以装插件。** 桌面版也能装，但不是必须。

之前这里写的是「只能装在 Tauri 桌面端，手机装不了」——
那是我把官方报错文档读错了。官方那句是：

```
plugin.install.unsupported
在非 Tauri 环境（Web/WASM）尝试安装插件时触发
插件安装仅支持 Tauri 桌面端，Web/WASM 不支持
```

它说的 **Web/WASM 环境** = **浏览器里的 AstroBox 网页版**。
手机上的 AstroBox 是**原生 App**（Android / iOS），不是 Web，所以**能装插件**。

（用户实测确认过。）

这条结论很关键 —— 它决定了整个方案的可行性：
手环用户是用 AstroBox 装我们 App 的，**他们手机上本来就有 AstroBox**，
所以插件是**零额外安装成本**。如果只有电脑能装，这个方案就没意义了。

## 一、准备插件包

已经打在仓库里了：

```
plugins/astramai-bridge/astramai-bridge-0.1.0.abp
```

如果你的 AstroBox 更认 `.zip`，同一个文件改个后缀就行
（`.abp` 本质上就是 zip，里面是 `manifest.json` + `plugin.wasm` + `icon.png`）。

体积 **7.4 MB**（解压后 20.5 MB，里面是 CPython）。

## 二、安装

1. 电脑上打开 AstroBox 桌面版
2. 进「插件」页
3. 找「安装插件 / 导入插件」，选上面那个 `.abp`
4. 装完**启用**它

> 具体菜单叫什么我没法确认（看不到你的应用），
> 反正就在插件页里。如果它让你选文件，选那个 `.abp` 就行。

## 三、看日志 —— 这一步才是重点

插件 `on_load` 里有一段**联网自检**：打一次我们服务器的 `/api/health`
（那个端点免鉴权），然后把结果打进日志。

装好启用后，找到**插件日志**（通常在插件详情页里），看这几行：

### 情况 A：网络通 ✅

```
[astramai] ✅ 网络可用（/api/health: 200）
[astramai] 已订阅 <你的手表名> (<地址>)
```

**两行都出现** → 网络通、interconnect 也注册上了，这个方案成立。

### 情况 B：网络不通 ❌

```
[astramai] ❌ 网络不可用：连不上服务器：...
```

**这条路死了。** 说明宿主没有实现 `wasi:http` / `wasi:sockets`
（虽然产物里 import 了，但宿主要提供才行）。

那就只能换方案：
- 让手表自己联网（eSIM 表没问题，手环不行）
- 或者把中转做在服务端/别的通道上

### 情况 C：订阅失败

```
[astramai] 现在没有已连接的设备——连上手表后需要重新加载插件
```

网络可能是通的（上面那行 ✅ 在就行），只是手表没连。
**先把手表连上，再禁用+启用一次插件**（重新触发 `on_load`）。

## 附：如果装都装不上

常见原因（按官方报错文档）：

| 报错 | 原因 |
|---|---|
| `plugin.install.unsupported` | 用的是 Web 版，换成 Tauri 桌面版 |
| `plugin.install.failed: store base empty` | 插件存储目录权限问题，重启 AstroBox |
| `Plugin '...' is not loaded` | 装得不完整，重装 |

## 附：这份插件现在能做什么、不能做什么

**能**：接收手表消息、回消息（分片）、请求我们服务器。

**还不能**：

- 没配置界面（服务器地址写死在 `src/app.py` 的 `SERVER_BASE`）
- 只在 `on_load` 时订阅一次；如果那时手表没连上，得手动重载插件
- 手表端还没有对应代码
